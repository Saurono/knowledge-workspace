# 共享服务协议与资源用例

领域层定义 v1 成功/错误信封、分页、版本前提、项目/资源/事件模型。应用层复用 Wiki 路径规则及 memory/domains 校验，注入共享仓储、ID 和时钟，提供项目、Wiki、工作区与事件用例；HTTP SDK 经传输端口调用，不持有数据库或文件路径。

`server/` 是 Node 24 适配：SQLite 保存版本资源和事件，同事务提交；删除保留版本墓碑，重建资源不会重复旧版本。HTTP 要求部署连接密钥，GET 健康信息不需要认证；更新/删除必须携带 If-Match，创建用 If-None-Match: *。分页游标绑定资源范围，读取/更新均校验项目。

当前共享资源覆盖项目、Wiki、记忆/领域工作区和文档目录元数据；上传/SSE/独立 Web 入口在 C03 接入。旧 Rust Agent 引擎和桌面数据未被复制或自动同步。

服务连接密钥不是 user/agent/admin 登录；C05–C09 负责登录、Token、访问上下文和细粒度授权。当前所有认证连接都属于部署者信任域，不能直接作为多租户隔离服务发布。SQLite 集成测试使用真实 HTTP 和临时磁盘，覆盖重启、并发、墓碑、事件、分页和错误保护。

C03 已接入文档接收、受认证 SSE 和独立 Web 静态入口。上传只保存服务生成 ID 下的独立二进制和 received 元数据；元数据失败时清理对应二进制，目录 ID 重用不能覆盖旧上传。断线按持久序号恢复。SQLite 与文件写入不是跨介质事务，进程在文件落地后、元数据提交前崩溃可能留下孤立二进制，恢复清理仍需后续工作，不能据此伪报入库完成。
