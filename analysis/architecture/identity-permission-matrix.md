# C04：账号、成员与工作角色

状态：已实现模型、可信内部目录用例、纯权限求值与 SQLite 持久化。登录/Token/可信 AccessContext/委托/HTTP 全路由授权分别属于 C05–C09；当前服务仍使用部署连接密钥，账号目录尚不参与 HTTP 请求鉴权。

## 账号类型与全局权限

| 类型 | 登录通道（模型约定） | 创建项目 | 管理账号 | 自动获得项目内容/私有记忆 |
| --- | --- | --- | --- | --- |
| user | 交互式登录 | 是 | 否 | 否 |
| agent | API Token | 否 | 否 | 否 |
| admin | 交互式登录 | 是 | 是 | 否 |

停用账号的全局/项目权限均为空。账号 handle 使用 NFKC、去空白和小写规范化，全目录唯一；账号 ID 稳定，不随 handle 或角色变化。目录只包含身份元数据，不保存密码、部署连接密钥或 Agent Token。C05 需实现首次管理员引导与认证凭据仓储；创建项目时授予创建者成员身份也由可信组合层完成。

## 项目成员权限矩阵

每个账号在一个项目最多有一条成员记录，记录 active/revoked 状态、权限级别和获授工作角色列表。同一 agent 可加入多个项目；被撤销的成员记录保留身份和历史引用。

| 操作 | viewer | editor | manager |
| --- | --- | --- | --- |
| 读取项目、Wiki、文档、项目范围内记忆 | ✓ | ✓ | ✓ |
| 写入 Wiki、文档、记忆 | — | ✓ | ✓ |
| 管理领域、运行 Agent、管理任务 | — | ✓ | ✓ |
| 管理项目设置、成员、工作角色 | — | — | ✓ |
| 管理全局账号 | — | — | — |

这里“读取记忆”只是操作级基础权限，不能替代 F 系列对角色共享范围、资源可见性和私有授权的判断。manager 也不能提升自己的账号类型。账号 admin 不隐式成为任意项目 manager；管理账号与读取知识是不同权限。

## 工作角色与切换

工作角色归属于一个项目，包含名称、说明、active/retired 状态、权限级别及显式操作列表。角色不能包含全局权限；操作列表必须落在该角色权限级别内。成员获授角色时，角色级别不能超过该成员级别，跨项目角色引用被拒绝；升级已授角色也不能绕过成员上限。

纯求值函数只接受已存在且获授的有效角色。选中角色后，有效操作为角色显式权限、角色级别及成员级别的交集；角色身份与有效权限一起切换。未选择角色时只计算成员基础权限，不据此推断任何角色共享记忆权限。退休角色保留引用但不能被激活；撤销成员或停用账号后，即使持有旧角色 ID 也被拒绝。

C08 负责可信会话内切换和委托，C07/C09 负责每次请求构建及重新验证有效上下文。客户端传入 accountId/workRoleId 不构成认证，角色 ID 也不是凭证；当前纯函数不能直接作为公开授权端点。

## 私有记忆

私有记忆检查在成员/角色操作权限之后追加，默认拒绝。显式 grant 必须同时匹配账号、项目、记忆 ID 和 read/write 操作；可设置过期时间，等于当前时间即失效，无效时间也拒绝。管理员同样需要 grant。grant 必须由未来可信授权仓储产生，不能信任客户端自报；F 系列还需实现授权记录、撤销、资源过滤与审计。此处没有创建新的用户记忆分类或星体映射。

## 持久化与变更规则

identity 模块独立拥有领域规则和目录端口，server/identity.ts 注入 Node SQLite；业务模块不读取数据库，不依赖 Tauri/Store。目录修订从 1 开始，每次有效修改整体递增；更新要求提供预期修订，旧修订拒绝并返回实际修订，不能静默覆盖。跨连接更新经 BEGIN IMMEDIATE 串行事务完成，失败回滚；无变化保留修订。

服务数据库 schema 1→2 只增加单行 identity_catalog 表，不改项目、资源、资源版本、墓碑或事件。空目录不是默认管理员；首次引导留给 C05。旧库首次打开迁移，新库直接建立基础表再升级；未知高版本或损坏身份目录拒绝启动，不清空覆盖。迁移不生成项目内容变更事件，也不把部署连接密钥迁成账号。

目录用例拒绝停用最后一个有效 admin；可先建立第二个 admin 再停用旧账号。当前内部接口只允许可信组合调用，未开放绕过认证的管理 HTTP 路由。
