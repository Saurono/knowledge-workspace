# ADR C01：桌面、共享服务与离线边界

状态：采用。本文记录 C01 的部署决策与当时 C01–C04 范围。C01–C10 现已全部完成；账号、Token、委托、授权和 UI/审计的当前行为见 [操作手册](../implementation/shared-service.md)。文中早期“部署连接密钥”数据访问过渡已关闭，密钥仅用于首次 admin 初始化。

## 两种运行模式

| 模式 | 权威数据 | 前端连接 | 离线行为 |
| --- | --- | --- | --- |
| 桌面独立 | 用户本机项目文件和原生历史/索引 | 原 Tauri 应用、已有模块端口 | 本机文件/编辑/本地能力可用；远程模型和搜索仍需网络 |
| 共享服务 | 服务端 SQLite 资源版本、上传文件和事件日志 | 独立 Web 入口；桌面可通过同一 HTTP SDK 连接 | 服务不可达时可保留当前编辑草稿，禁止伪报保存成功；不建立隐式离线写队列 |

共享服务作为可独立启动的 Node.js 24 LTS 进程，不依赖桌面窗口、Tauri 或浏览器文件权限。复用 TypeScript 模块领域规则；存储/HTTP/上传/SSE 是服务适配器。现有 Rust Agent 引擎仍是工具/模型执行核心，不在新服务复制另一套 Agent 引擎。

Web 的首批实际能力是项目、Wiki 资源、记忆/领域数据、文档上传和项目事件。桌面原生解析、向量数据库、CLI/Shell、Vault/监听必须通过本机能力端口调用；没有桥接时明确不可用，不能因为浏览器与服务同机就访问任意本机路径。完整两端功能一致性需要后续任务逐个接入这些执行能力。

## 数据与版本

共享服务使用独立数据目录（默认 `.knowledge-workspace-service`，可配置），其中 SQLite 保存项目、版本资源和有序事件；上传二进制只使用服务生成的 ID/目录，客户端文件名仅作为元数据。数据库 schema 版本受控升级，不能静默覆盖未知新版本。

C02 统一 `/api/v1`、错误、分页游标和 ETag/If-Match 版本协议；资源更新采用条件写，冲突保留草稿。资源写入与对应事件在同一数据库事务提交。事件可按序号恢复；SSE 断线后从最后序号重连。接收上传不等于解析、编译或索引已完成。

现有桌面 JSON/原生历史格式保持兼容。共享服务数据库不是桌面项目文件的自动镜像，也不让两个进程绕过版本协议共同修改同一资源。

## 同步与连接

本阶段不做双向自动同步、最后写入获胜或跨机器文件路径复用。导入/导出是显式动作；未来同步须携带来源 ID、资源版本、幂等键和冲突记录。浏览器上传文件属于显式复制，服务端接收时间与来源历史时间分开。

Vault 在用户本机，Web 不直接挂载；未来 D08 通过受限本机连接器投递独立 JSON 回执。Shell 与监听同理，不接受 Web 提供的任意本机绝对路径。CLI 安装/登录状态不能由服务端虚构。

## 服务暴露与凭据

服务默认只监听 `127.0.0.1`，Web 与 API 同源部署。远程访问需显式配置监听地址并由 HTTPS 反向代理终止 TLS；不默认开放任意 Origin。

在 C05 人员登录和 C06 Agent Token 完成前，使用部署者配置的服务连接密钥保护共享 API；密钥只在运行环境/浏览器当前内存中使用，不写到仓库或浏览器长期存储，不以它冒充人员账号。健康/协议版本可公开，项目数据、上传和事件必须认证。后续认证替换此适配，不改变业务仓储协议。

C04 仅建立账号/成员/工作角色模型、校验和权限矩阵，不提供已完成登录或已实施全路由账号授权的承诺。

## 运行与验收

C02 提供独立服务构建/启动与真实 HTTP/SQLite 回归；C03 提供本机端口适配、Web 上传/API/事件连接和独立前端构建。启动参数与操作手册随代码落地更新。验收必须验证进程重启后持久化、冲突写入、分页、事件恢复、上传失败和无凭据拒绝，预览内存 FS 不能作为服务端验收证据。
