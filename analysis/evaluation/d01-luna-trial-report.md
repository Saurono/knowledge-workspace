# D01 试运行与 Luna 编码评估报告

日期：2026-11-01 UTC。基线：`f4c9bb2`。仓库：Saurono/knowledge-workspace；分支：`codex/knowledge-workspace-v0.1`。

## 结论

**D01 产品版本经 Luna 编写、主控两轮功能审查返修及独立验收后，可以作为本阶段的状态与检查点基础使用。Luna 首版不能直接按“自测通过”交付；本次也没有证据证明该分工节省了实际 Token。**

同题首版必需行为验收：Luna **11/15（73.3%）**，主控同模型隔离对照 **15/15**；额外旧数据保护分别为 0/1、1/1。但主控对照首版重放类型检查也失败，说明测试通过不等于可构建。两组审查整改后均通过共同 16 项验收和类型检查。这些是本次 D01 验收结果，不是模型总体准确率或通用排名。

## 1. D01 交付范围

- 五阶段：接收、解析、知识编译、索引、回传；显式记录 pending/running/succeeded/failed/blocked/cancelled/skipped。
- 依据阶段证据区分内容可用、知识就绪、实际回传和整体完成，避免部分成功报全成功。
- 不可变转换、attempt/attemptId 拒绝迟到结果、阶段依赖/时间校验、独立重试和中断恢复。
- 既有文档资源中的持久检查点、CAS 条件版本、元数据保留和损坏保护，无数据库 schema 变更。
- 上传只登记接收成功；受 documents.read 保护的只读查询及强类型 SDK：GET /api/v1/projects/:id/documents/:documentId/ingestion。

真实解析、模型编译、索引和 Vault 执行器未接入本项；后续阶段用例为故障注入/规则验证，不冒充真实外部处理。恢复由受信任编排层显式调用，D01 不提供自动恢复调度器；外部证据引用的真实性仍由后续执行器保证。旧桌面队列 done 含义未改，文档页没有另建任务进度列表。

## 2. 对照方法

| 项目 | 方法 |
| --- | --- |
| 产品编码 | gpt-6-luna 子代理；产品代码采用此组 |
| 对照编码 | 继承主控模型的独立代理；工具未返回实际底层模型/计费标识，不臆测型号 |
| 输入 | 两组均独立上下文、相同 Git 基线、同一[固定任务书](d01-trial-brief.md) |
| 隔离 | 对照在独立 worktree；两组被要求不读对方实现；对照代码只作评估快照 |
| 独立检查 | 另一 Luna 从任务书生成测试，主控先审查假设，再对两组运行同一[16 项验收](d01-acceptance.test.ts) |
| 评分时点 | 自测后先冻结首版，再做有效验收；返修不改写首版分数 |
| 审查后对照 | 两组接受相同的错误码、元数据、时间/证据保护和输入校验清单 |

独立测试初稿也存在默认 policy、字段归属、旧数据夹具、权限预期等错误。主控在计分前修正，不能把测试自身错误计为模型缺陷。**测试生成同样需要审查。**

只有一个任务样本；测试在任务书及代码审查中完善，属于工程验收，不是预注册双盲基准。每个用例还包含多个断言，通过率不代表所有潜在输入均正确。

| 必需合同用例 | 11/15 | 15/15 | 15/15、15/15 |

Luna 四项必需行为失败：

| 编号 | 首版问题 | 整改 |
| --- | --- | --- |
| R01 | parse 被阻塞时汇总为 failed | waiting，区分等待条件与执行失败 |
| R02 | parse 成功、compile 未开始仍报 processing | waiting，不暗示执行器还在运行 |
| R03 | compile 成功后 index 取消只报 cancelled | 保留 contentReady，整体为 partial |
| R04 | 缺跨阶段时间校验 | 后序 startedAt 不早于已完成上游 finishedAt |

额外 R05：read 拒绝无可靠接收依据的旧数据，save 却能加新快照绕过；现已统一检查读写依据。另补可选兼容字段、SDK 类型、结构化生命周期错误、安全整数版本/计数、不可变 policy/接收证据、严格旧数据校验及非法编码 400。这些整改未混入原 15 项首版分数。

产品经两轮主控功能返修，再补 CI/真实 SDK 断言。对照也接受等效审查，并修正其首版漏做的末次类型检查；代理自述没有直接作为验收结论。

证据：[Luna 首版验收](artifacts/d01-luna-initial-acceptance.txt)、[对照首版验收](artifacts/d01-primary-control-initial-acceptance.txt)、[对照首版类型错误](artifacts/d01-primary-control-initial-typecheck.txt)、[Luna 最终验收](artifacts/d01-luna-final-acceptance.txt)。首版/审查后 patch 均在 artifacts，重放需回到基线。

## 5. Token：实测边界与文本对照

### 真实消耗

| 对象 | 输入 / 输出 / 推理 / 缓存 / 总 Token |
| --- | --- |
| Luna 产品编码及返修 | **不可获取** |
| 主控同模型对照 | **不可获取** |
| 独立测试生成 | **不可获取** |
| 主控拆分、调度、审查与报告 | **不可获取** |

collaboration 工具没有返回 usage 计数，可用日志也没有本会话计费数据。因此不编造实际用量、不估币费，亦不把对照代理产出当作主控本轮全部消耗。

### 可复现的可见文本计量

以 gpt-tokenizer@4.1.0 的 o200k_base 统计同一基线 patch 新增实现/测试文本。共同任务书为 **1776 个该编码口径的 Token**；不是完整输入量，也未证明该编码等于底层计费编码。

| 可见新增文本 | Luna 首版 | 主控同模型首版 | Luna 审查后 | 对照审查后 |
| --- | ---: | ---: | ---: | ---: |
| 实现 | 4780 | 4224 | 5716 | 4672 |
| 测试 | 2437 | 4219 | 5473 | 5445 |
| 实现＋测试 | **7217** | **8443** | **11189** | **10117** |

首版 Luna 测试文本较少，最终为返修和验证增加了代码/测试。审查后产品另有 CI 接线和 SDK 断言，收尾范围略有差异。**快照文字量不是累计生成量，更不是实际消耗：不含源码/工具读取、隐藏推理、返修替换文本、缓存和主控审查成本，不能声称“省了多少 Token”。**

[首版计量](d01-visible-token-metrics.json)、[审查后计量](d01-reviewed-visible-token-metrics.json)、[脚本](d01-measure-text.mjs)、[元数据](d01-trial-metadata.json)可复核。控制组特有的 node_modules 实验链接已排除。

重放时在项目外安装上述 tokenizer 版本，设置 D01_TOKENIZER_MODULE 为其 esm/encoding/o200k_base.js 的绝对路径，再运行：

```bash
node analysis/evaluation/d01-measure-text.mjs
node analysis/evaluation/d01-measure-text.mjs --luna analysis/evaluation/artifacts/d01-luna-final.patch --control analysis/evaluation/artifacts/d01-primary-control-reviewed.patch
```

若要决定实际降本效果，需平台按代理/任务导出的 input、output、reasoning、cached usage 与费用；本轮缺少这些证据。

## 6. 时间与建议

可验证可见窗口：Luna 从 checkpoint.ts 创建至末次首版自测日志约 4 分 57 秒；对照对应窗口约 4 分 04 秒。不含全部前置调查，也不是推理耗时。模型粗报起止时间有偏差，未用于速度或计费结论；元数据保留文件时间和快照 hash。

建议继续将 Luna 用于范围明确、契约清晰的编码，由主控掌握状态/权限/持久化规则并独立验收；暂不宜取消审查。首版边界漏项与对照类型漏检都支持保留“生成—审查—返修—复验”。是否比主控独立完成更省 Token，暂不能下结论。
