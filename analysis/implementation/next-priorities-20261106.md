> 取舍标准：只列会改变后续返工量或上线风险的项。已经在 TASKS 里的规划不重复列，只提改序。

## P0 — 先有尺子，再往前修

### K01 检索与记忆质量基线

问题：`analysis/evaluation/` 目前只有 D01/D02 的合同验收和 token 计量，没有检索质量指标。D05 索引、E03 检索、F 记忆都做完之后，没有任何东西能回答「比上一版好还是差」。

要做：
- 固定语料 30–50 条，中英各半，覆盖六类：精确名词、同义改写、跨页多跳、应当返回空、带领域过滤、包含未授权项目（必须被过滤掉）。
- 指标：recall@5、recall@10、引用命中率（引用页确实包含答案）、空结果误报率、越权返回数（必须恒为 0）。
- CI 用 mock embedding 跑，结果确定；真实模型单独跑，快照 JSON 作为当前基线。
- 脚本 `scripts/eval-retrieval.mjs`，报告 `analysis/evaluation/retrieval-baseline-*.md`。

验收：脚本在固定 fixture 上输出 JSON 并有断言；报告含基线与回归判定口径。

约束：K01 之前不要调 chunk size、topK、融合权重——调了也没法证明是变好。

### K02 共享 Web 检索最短路径（E03 提前）

问题：检索逻辑仍在 Rust 的 `search_project` 里，`server/` 只有资源工具。共享 Web 模式目前「能存不能找」。

要做：SQLite + FTS5 关键词检索先行，走 `src/modules/retrieval` 的同一套公开契约；授权过滤在 SQL 里完成，不做结果集二次过滤。

验收：越权查询返回 0 条；同一查询在本地与共享模式返回同结构结果（字段与排序契约一致）。

### K03 存储一致性规则：文件为唯一真相源

问题：Markdown 在文件系统、资源在 SQLite、向量在 LanceDB（仅 Rust 桌面端）三套各自提交。HANDOFF 已记录三次跨介质崩溃窗口。

要做：
- 在 ARCHITECTURE 写明：文件是唯一真相源；向量、图谱、星图、索引全部是可重建派生数据，**不给派生数据写迁移**，损坏一律重建。
- 增加 `rebuild-index` 入口和启动时一致性检查：派生缺失/损坏 → 标记 stale 并排队重建，不静默当 ready。
- 共享服务侧向量选型优先 `sqlite-vec`（与 SQLite 同库、同事务语义），与桌面端 LanceDB 之间只通过检索端口隔离。

验收：删除派生目录后重建，检索结果与删除前一致；重建期间不返回空集。

## P1

### K04 写入门：候选、审核、生效最小闭环（F03/F06 前置）

问题：C09 已让 Agent 能写 Wiki 与记忆，但 F06 的候选/冲突/过期、E07 的回流审核都还没做。现状是「能写不审」。

要做：写入先落 pending（带幂等键、来源、模型标识、证据），规则+人工批准后转生效；冲突检测复用现有 revision/ETag 语义。

验收：同一提案重复提交只生效一次；未批准的写入不出现在检索结果里，也不被注入 Agent 上下文。

### K05 Model Gateway 与用量记账

问题：embedding 批量、两阶段 ingest、deep research 都在调外部模型，但没有 usage 落库、项目配额、降级策略；D01 报告也说明真实 token 拿不到。

要做：单一出站模块，强制记录 provider/model/prompt/completion/cache/耗时/项目/操作者；项目级预算；超预算降级到本地 embedding 或显式跳过。

验收：断网、超配额有明确错误码，不静默失败；审计里能查到每次调用的计量行。

### K06 D05 索引状态机（保持原计划，收紧一条）

unknown 不得当 ready；索引失败必须能独立重试；重建期间旧索引可服务或明确返回 stale，不能返回空集。

## P2

### K07 原生构建与安装包（J04 提前）

十八模块边界、共享服务、浏览器全流程都验过了，但环境无 cargo，桌面安装包从未构建。这类风险留到最后一次性爆发最难定位。建议先跑通一次最小可安装包，同时把新仓库 CI 修绿。

验收：本机产出可安装包并能启动到首屏；CI 有对应 job。

### K08 数据生命周期

来源级删除级联（文件、SQLite、派生索引）、孤儿上传目录清理、项目导出可回灌。与 J01 合并做。

### K09 星图视觉（G02/G03）降级到最后

差异化在「编译出的知识可审计、能回到来源」，不在三维外观。

## 不建议做的

- 在 K01 基线建立前调检索参数。
- 在 K04 之前继续扩大 Agent 写权限。
