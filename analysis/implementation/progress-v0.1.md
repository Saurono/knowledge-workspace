## 已实现的第一批可运行功能

- 对话页“本地搜索 / LLM 对话检索”切换。本地搜索不传远程 Embedding 配置，可按已分配领域筛选返回结果；LLM 保持原生 Agent 链路。
- 移除侧栏独立搜索与 Lint 入口。Wiki 页提供编辑/预览切换，整合原检查、修复与规则操作。
- 统一任务管理器三个标签，汇总现有入库队列、研究面板及检查/纠错活动；移除原业务布局中的 Activity 和研究任务侧栏。
- 检查执行移到页面外，可离开 Wiki 到任务管理器取消；项目切换后不注入旧项目检查结果。
- 本地项目持久化的扁平多选领域；Wiki/来源预览可归类；记忆与本地搜索有领域筛选。
- 本地记忆页：创建、修改、搜索、删除、领域归类和显式记忆关联。分类字段可留空，等待用户的专门分类方案；不自动提炼聊天或向模型注入记忆。
- 三维记忆星海：按指定参考项目适配 Canvas 透视投影、星尘、光晕、星团、拖动旋转、缩放、右键/Shift 平移、标签、焦点高亮、详情和视角复位。动态效果默认关闭。Wiki 与记忆分别供数，保留原 Wiki“图谱分析”入口。
- Obsidian 本地连接配置在任务管理器的文档导入标签。手动从已连接 Vault 导入的来源保留原路径，排队入库成功后写独立 JSON 回执，原笔记内容不变；回传失败保留 pending 并可单独重试。
- Wiki 页面显示建立时间与逐来源首次入库时间。数据记录在项目 sidecar，旧数据无可靠时间时显示未知；更新不会重置已记录的建立时间。

## 当前实现的实际边界

1. 这是本地桌面代码的第一批改造，尚未完成可独立使用的 Web 后端、user/admin 登录、agent 账户 Token 管理和服务端权限。这些不能用前端切换或现有全局 API Token 代替。
2. 领域是本地项目元数据。尚未把领域范围传入后端 LLM 证据检索；当前搜索领域筛选发生在返回结果中，不能作为权限隔离。
3. 记忆当前由人手动管理，本地存储不含多人隔离与 Agent CRUD API。记忆分类、自动提炼、生效/归档策略以及模型读取等待后续方案。
4. 任务管理器目前对既有执行器做前端汇总。入库仍有原生持久队列；研究/检查活动记录主要随当前进程保留；尚未建统一后端持久任务服务。文件复制和预解析也尚未全部变为可恢复任务阶段。
5. 回执首批记录成功内容入库；未声称覆盖全阶段状态。由于原生向量化错误为非阻断，回执 indexStatus 记录 unknown，不伪报索引就绪。自动同步/外部 API 的源路径映射、Vault 文件移动和跨设备连接器仍待接入。
6. 现有页面合并与新页面生成的创建时间来自本批执行过程捕获。早期页面、部分失败写入以及直接调用旧 autoIngest 且未给 taskId 的路径可能没有可靠时间；暂不伪造，也尚未将全部元数据写进 Markdown frontmatter。
7. 星图保持当前数据语义；Wiki 连线可含推断关联，记忆只画显式关联。最多显示 4,000 节点和 12,000 连线，超限有提示；不载入参考项目的默认记忆分类或演示数据。
8. Obsidian 回传配置写入本机文件夹，尚未实现 Web 到本机 Vault 的桥接。收据目录硬排除于前端来源过滤和 Rust watcher，避免自导入循环。

## 数据与操作

- `.llm-wiki/workspace.json`：领域、资源归类、手动记忆及关联；串行更新、原子写入、损坏时拒绝覆盖。
- `.llm-wiki/ingest-records.json`：来源、页面时间、回执、Vault 连接和投递状态。
- `<Vault>/kb-ingest-records/<receipt-id>.json`：供外部软件读取的独立回执，schemaVersion=1。包含 taskId/sourceId/sourceRevision、内容入库状态、原始来源路径及 Wiki 结果时间。
- 开发启动：`npm ci`，`npm run dev`；桌面功能仍需 `npm run tauri dev` 和完整 Tauri/Rust 环境。

## 推荐接续顺序

先补统一任务协议与执行器持久化，再实现账户授权和 Web 平台适配；同步补齐来源稳定身份、自动同步到 Vault 的回执、索引真实状态及完整时间写入链路。收到专门记忆分类方案后再扩展记忆模型和 Agent 接口。

浏览器验证脚本见 smoke-workspace.mjs；需另行安装 playwright-core 并设置 PLAYWRIGHT_MODULE 和 CHROMIUM_PATH，先运行 Vite。它使用原生 API 模拟器，不用于连接生产知识库。
