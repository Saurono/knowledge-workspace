# D03 领域归类与筛选契约

日期：2026-11-03（Asia/Shanghai）；基线 `757cb1c`。本轮按用户授权完成 D03/D04，D05 仅设计契约。主控确定接口/验收与提交，Luna 编写程序和测试。

## 数据与兼容

- 领域保持项目内扁平标签，一份 Wiki/来源可多选；不引入父子层级或跨项目共享。
- 沿用 workspace v1 的 domains/resourceDomains 作为权威关联，分类不写入原始笔记。Wiki 的 tags/page type 不等同于领域。
- Wiki 资源键沿用规范 `wiki/...` 相对路径；有稳定来源 ID 的文档统一使用逻辑键 `raw/documents/<sourceId>`，它不是实际文件路径。同源不同修订共享归类；不同来源即使同内容仍分开。
- 本地已有 `raw/sources/...` 记录兼容读取：规范来源键存在时（包括显式空数组）以其为准，否则读取已验证同源的旧路径键。首次明确编辑后使用规范键。未能确定来源身份时不猜测合并，不抹去旧分类。
- 未知或已删除的领域关联不算有效分类；只读投影可显示为未分类，不借读取静默重写旧记录。删除领域通过现有受保护更新清理关联。

## 统一筛选

- 多选领域默认 ANY，可显式 ALL；无选择表示不限制领域。
- 未分类是独立筛选条件，不是特殊领域 ID；不与非空领域选择混用。
- 域 ID 去重、规范排序以形成稳定查询语义；未知领域查询明确拒绝，不悄悄变成全部结果。
- 本地资料、Wiki 导航和搜索证据以及共享 Wiki/documents 列表复用同一纯规则。领域不是访问控制，服务端先授权再筛选。
- 服务分页先筛选再取页，游标绑定项目、资源类型和规范筛选条件；更换筛选不能复用旧游标。
