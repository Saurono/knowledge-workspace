# D05 实际索引结果契约草案

初稿：2026-11-03（Asia/Shanghai）。2026-11-06 用户将授权扩大为完成 D01–D09；D05 现允许实施，完成勾选仍需真实提交与验证证据。现有入口为 ingestion 的五阶段 checkpoint/lifecycle 与 retrieval 的公开 embedding/search 端口。

## 目标与权威证据

编译成功后保留 contentReady；只有可信索引端口实际提交并验证输出，才将 index 标为 succeeded。配置 required 时，未知、未开始、失败、取消均不能当作 ready。disabled 必须是明确策略，不能因网络或供应商故障临时切成 disabled。

每次索引工作需固定项目、稳定来源、内容修订、编译输出集合及其内容修订、索引提供者/模型/维度/配置版本、索引代次和 attemptId。时间、成功计数和证据由受信任适配层提供，客户端不能写一个布尔值宣布成功。

成功证据应能定位持久索引提交及其清单，并能查询验证预期输出是否全部可读。成功计数、部分失败、空结果分别表达；不能把 HTTP 200、入列成功或模型请求结束等同于索引提交成功。

当前端口缺口：`retrieval/application/ports.ts` 的 VectorIndexPort.upsert 返回 Promise<unknown>，只有 page 级写入/搜索/删除/计数等能力，没有显式代次提交、清单校验和发布证明。D05 实施必须先补足或适配这些能力，不能把旧 upsert 的返回值直接包装成可信成功回执。模型传输与索引持久化仍分开注入，不能因调用了 embed 就宣告检索可用。

## 并发、重试与恢复

- 索引幂等身份包含项目/来源/内容修订、输出清单摘要和索引配置版本；同代次重复尝试不重复发布相同 chunks。
- 仅重试 index，不重新编译、不重设来源首次入库时间、不再发送已确认回执。重新编译或配置变化产生新代次。
- 保存 checkpoint 仍使用资源 CAS；旧修订、旧 attempt、已取消或已撤权的迟到结果不得覆盖当前状态。
- 部分写入保留明确 pending/failed 或 blocked，并由适配器提供恢复/清理策略。发布新代次前完成验证，避免用户查到半份新索引；旧代次何时撤下需按查询端契约确定，不能先删后赌重建成功。
- 服务重启后先核对索引端证据再恢复；完整持久调度属于 H03，不在 D05 内假造调度器。
- 资源在处理或交付期间撤权，重新授权后才可继续写入或返回结果；领域过滤复用 D03，不能替代权限过滤。

## 验收清单

1. compile 成功/index 尚未运行：内容可用但知识未就绪。
2. index required/提供者不可达：明确失败或等待，不能 skipped/succeeded。
3. 部分 chunks 写入失败：不发布完整成功；独立重试后无重复 chunks。
4. 同输入并发重试：只有一个可验证的逻辑发布结果。
5. 索引中源修订或输出版本改变：旧结果拒绝，当前编译结果不被替换。
6. 已完成索引代次被删除/损坏：查询校验报告损坏或待恢复，不继续显示 ready。
7. checkpoint CAS 冲突、进程中断和重启：已有知识输出保留，恢复有证据。
8. 只读 Token、跨项目、运行中吊销/角色切换：各阶段权限拒绝保持一致。
9. index 明确 disabled：可以 skipped，但界面清楚表明未建立实际索引。
10. 用至少一套真实临时索引存储证明提交/重开/查询；模型或外部提供者仍模拟时，报告分开标注，不冒充生产外部链路验收。

实施前仍需主控审查实际索引适配器的提交/代次能力，确定能实现的发布边界。旧数据缺少可验证证据时保持 unknown；不得仅为了展示为 ready 批量回填成功。
