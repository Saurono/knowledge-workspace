# D02 来源、修订与幂等验收边界

日期：2026-11-02（Asia/Shanghai）。工作分支：`codex/knowledge-workspace-v0.1`。
基线：`36caffb74e5b41b942ef051ce8293f55c163e143`。实现及测试由 Luna 编写，主控确定契约、审查并独立运行验证。

## 固定契约

- 来源 ID 表示项目内的逻辑来源；路径表示位置，内容摘要表示修订。相同内容的两个独立来源不会自动合并。
- 同一外部原路径重复导入复用已登记目标；内容变化属于同源新修订。同名不同原路径不覆盖彼此。
- 复制前可预留来源 ID 和目标位置，预留不表示接收完成；复制失败保持 `receivedAt=null`，重试复用原预留。目标分配同时检查磁盘内容与其他来源的预留。
- 已确认的移动保留来源 ID 和历史；目标身份冲突必须在修改正文和引用之前拒绝。旧数据和损坏数据不能静默重置。
- 编译幂等身份包含项目、稳定来源、实际编译输入修订和操作，不包含路径、随机任务 ID 或重试次数。排队时的预估输入不能冒充真正编译修订。
- 原始上传字节 SHA-256 与解析文本 SHA-256 分开记录。只确认接收的上传不能报告编译、索引或 Vault 回传成功。
- 相同成功修订仅在输出仍可验证存在时复用；缺失输出允许修复。已有图片补全和明确的修复行为保留。
- 写入失败、输入变化和取消不能把未持久完成的操作报告为成功；已完成的正文写入保留，避免危险回滚。

## 共享上传协议

`POST /api/v1/projects/:projectId/documents` 接收原始请求体。`X-File-Name` 使用 URL 编码；`Content-Type` 表示媒体类型。

- `Idempotency-Key` 标识一次接收请求；同键同语义重放原结果，改正文、文件名、媒体类型或显式来源意图返回冲突。
- `X-Source-Id` 指向本项目已有来源以接收新修订；无来源标识表示独立新来源。不能借用其他项目来源。
- `X-Create-Source: 1` 是明确的新建来源意图，可配合项目内调用方指定的来源 ID；它本身不授予任何项目或上传权限。来源选项需要同时提供幂等键。
- 同源同字节修订即使用不同请求键也复用；不同源同内容不合并。
- 旧无键客户端保持接收兼容；其已返回的来源 ID 可用于后续显式修订。
- 每次创建与重放重新授权；请求键和摘要不代替权限。仅持久化请求键摘要，不保存原值。
- SQLite 事务同时登记来源、修订、请求绑定、文档资源及事件；字节先落在独立目录，失败方只清理自己的目录。

接收响应沿用 `201` 与资源信封，重放返回原资源及其当前 revision/检查点。`data.sourceRevision`、`data.byteSha256` 与兼容的 `data.sha256` 都表示原始字节摘要；`revisionKind=raw-bytes-sha256`，尚无解析结果时 `parsedTextRevision=null`。重放会验证已发布字节的大小和摘要，丢失或损坏时明确失败，不从新请求静默覆盖旧文件。

Web 适配在同一连接实例内保留同一个 `File` 对象、项目和来源意图的默认请求键，供请求重试复用。跨连接实例或重启重试的调用方应自行持久保留显式键。不同 `File` 对象默认代表独立接收操作；没有可验证来源身份时，不通过文件名与内容摘要猜测它们是同一来源。

## 验收范围

1. 实际本地导入、队列和编译入口：重复、改版、同名异源、移动、并发、失败重试及输出丢失。
2. 旧 catalog、queue 和 receipt 兼容，坏数据保护；第一时间和历史证据保留。
3. 真实 HTTP、临时 SQLite 与磁盘上传：并发唯一性、冲突、重启重放、旧来源改版、跨项目和权限拒绝。
4. 模块边界、公开接口审计、类型检查、完整模拟回归及受影响构建。

本任务不实现 D03–D09 或 H/I 的完整执行器，不以测试注入代替真实模型、Vault 或原生桌面验收。最终实现、验证数字和剩余限制以 WORKLOG 中 D02 完成记录为准。

本地来源目录、复制、Wiki 输出与队列不是跨文件事务，互斥只覆盖同一应用进程。进程在输出落盘与回执登记之间崩溃仍存在恢复窗口；已有缓存/回执用于重试复用，不能将其描述为跨进程的严格恰好一次执行。上传的文件暂存与 SQLite 事务也属于两个介质，崩溃可能留下未发布目录；本阶段不自动删除这些真实数据。
