## 5. 备份 / 恢复

### 备份范围

- **每个知识项目根目录整体**：Markdown 是 Wiki 内容唯一真相源，原始资料、图像、附件也要保留；仓库源码备份不能代替知识项目备份。
- **`<项目>/.llm-wiki/` 整体**：workspace、索引、证据、历史、任务和用量记录。部分状态无法仅由 Markdown 重建。
- **服务数据目录整体**：默认 `.knowledge-workspace-service/` 或 KW_SERVICE_DATA；至少包含 `service.sqlite`、存在的 `service.sqlite-wal`、`service.sqlite-shm`，并保留 `uploads/` 原始上传文件。数据库还含身份、令牌摘要、权限和审计，丢失它不只是丢失搜索缓存。
- **`mcp-server/` 配置**：保留 package.json、package-lock.json、tsconfig.json，以及 MCP 客户端实际使用的配置文件与启动环境配置。仓库不规定统一的 MCP 客户端配置路径；实际路径/存在性未验证，应在备份清单填写，不要假设有 `.env` 自动加载。
- **桌面配置 / 凭据文件**：Rust 使用 `app_data_dir()/app-state.json`，Windows 预期 `%APPDATA%\com.llmwiki.app\app-state.json`；本轮只检查该路径存在，未读取内容。外置环境配置/凭据文件由部署方选址，位置和存在性未验证。只登记路径及存在性，备份文件受限保存，不导出密钥到手册。

本轮默认 `.knowledge-workspace-service/service.sqlite` 不存在；这不能证明其他 KW_SERVICE_DATA 路径没有数据库。不得为了检查而启动服务创建新库。

### 停止 → 复制 → 校验

1. 暂停任务、关闭桌面，停止 connector 与 MCP 客户端；服务前台终端按 Ctrl+C 并等待进程退出。`server/main.ts` 处理 SIGINT/SIGTERM 并关闭数据库；确认无其他写入者后才复制。不提供仓库不存在的 stop/backup 脚本。
2. 选择项目和数据目录之外的新备份目录。复制项目整体（含隐藏 `.llm-wiki/`）、服务数据整体、MCP 配置和受保护配置；若 SQLite 旁路文件存在，必须同批复制。不存在则在清单登记不存在，不能把仍在写入的库当一致快照。
3. 对比源与备份的相对路径、文件数量、长度及逐文件 SHA256；清单记录 commit、schema 版本、时间与路径，不含凭据。以下是 PowerShell 运维建议模板，非仓库脚本；只读/复制，不会自动停止服务。替换变量路径后逐个范围执行，备份目的地必须新建且不在源目录中。

```powershell
$opsSource = 'D:\实际项目或服务数据目录'
$opsBackup = 'E:\备份\本次批次\对应目录'
Copy-Item -LiteralPath $opsSource -Destination $opsBackup -Recurse -Force
Get-ChildItem -LiteralPath $opsSource -Recurse -Force -File | Get-FileHash -Algorithm SHA256
Get-ChildItem -LiteralPath $opsBackup -Recurse -Force -File | Get-FileHash -Algorithm SHA256
```

需以相对路径配对校验摘要，两边清单必须完全覆盖；发现重解析点先核对实际目标和备份覆盖范围。上述复制/校验模板未验证，不能凭执行无报错认定完成备份。
